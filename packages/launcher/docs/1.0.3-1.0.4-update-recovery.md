# Recovering Windows installs on launcher 1.0.3 and 1.0.4

Launchers 1.0.3 and 1.0.4 have the same broken installer handoff (the updater
modules are identical in both release tags). The startup log from an actual
1.0.3 to 1.0.4 attempt shows that the 1.0.4 installer downloaded successfully,
then the PowerShell handoff exited with code 0 within the 750 ms probe. Both
versions treat *every* early exit, including success, as a launch failure and
keep the old application running. The updater subsequently offers **Download
page**. A later release cannot change code already installed in these versions.

For people already on 1.0.3 or 1.0.4:

1. Publish a signed launcher 1.0.5 NSIS installer and its `latest.yml` and
   blockmap together, using the normal release workflow. Check that the
   Windows download endpoint serves 1.0.5.
2. In 1.0.3 or 1.0.4, use **Download page** after the failed update (or open the Windows
   download page directly), then run the downloaded 1.0.5 installer. Close
   OpenAgents when prompted. If the existing installation is under a protected
   directory such as `Program Files`, run the installer as administrator and
   select the existing installation folder. Do not uninstall or erase user data.
3. Confirm the app reports 1.0.5. In-app updates after that use the restored
   direct launch and administrator fallback from 1.0.2.

Do not present 1.0.3 or 1.0.4 to 1.0.5 as an automatic in-app upgrade. The old binary
cannot be repaired by a new renderer or updater module before it installs that
new binary. The one-time installer run is the recovery path for this cohort.
